# Nubis Cubed (SIGGRAPH Advances 2023) — Page Catalog, Pages 81–100

Section context: all 20 pages carry the running header **"Nubis³ / Voxel Clouds / Sampling Density"**. This block of the talk explains how per-raymarch-step density is produced: the voxel modeling data (NVDFs) multiplied by profile remaps multiplied by 3D detail noise, plus the physical reasoning (water vapor / entrainment) behind the two detail types (wisps vs billows) and the new Alligator-based noises.

No speaker-notes text is embedded in the extracted pages (image-only slides); each section below records only what is visible on the slide itself.

## Page 86
- **Title:** "**Dimensional Profile**", subtitle "**Voxel Size: 8 m**".
- **Content:** The greyscale cloud (Dimensional Profile visualization) with two red sample dots: one inside the cloud, one outside in empty space. Below, HLSL-style pseudo-code (exact):
  ```
  VoxelCloudModelingData modeling_data = GetVoxelCloudModelingData()

  if (modeling_data.mDimensionalProfile > 0.0)
  {
      cloud_density = GetUprezzedVoxelCloudDensity();
  }
  else
  {
      cloud_density = 0.0;
  }
  ```
  `GetUprezzedVoxelCloudDensity();` and `0.0;` are boxed/highlighted on the slide. Meaning: the expensive "uprezzed" (noise-detailed) density evaluation runs only where the Dimensional Profile is positive; elsewhere density is exactly 0.
- **Parameter names:** `VoxelCloudModelingData`, `modeling_data.mDimensionalProfile`, `cloud_density`, `GetVoxelCloudModelingData()`, `GetUprezzedVoxelCloudDensity()`.

## Page 92
- **Title:** none — text-only slide, two lines (exact):
  - "**Decreasing Density = Curly Layered Wisps**"
  - "**Increasing Density = Layered Billows**"
- This is the core detail-type rule: where a cloud is evaporating/dissipating (density decreasing) the detail should be curly layered wisps; where it is condensing/growing (density increasing) the detail should be layered billows.
- **Formulas/constants:** the two equalities above.

## Page 93
- **Title:** column headers "**Nubis Noise**" vs "**Nubis³ Noise**"; row labels "**Billows**" and "**Wisps**".
- **Content:** 2×2 grid of noise slice thumbnails comparing old vs new noise bases:
  - Billows row: old = "**Worley**" (soft cellular bumps, low contrast); new = "**Alligator**" (cellular but with sharp dark crevice network between bright cells — much higher structural contrast, reads like billow creases).
  - Wisps row: old = "**Perlin-Worley**" (in quotes on slide; smooth blotchy fBm-like); new = "**Curly-Alligator**" (in quotes; feathery, swirled filament texture with dark voids — visibly curly/stringy).
- Takeaway: Nubis³ replaces Worley/Perlin-Worley with Alligator and Curly-Alligator noises for billows and wisps respectively.
- **Formulas/constants:** none numeric.

## Page 94
- **Title:** "**Voxel Cloud Noise**".
- **Stats text (exact):**
  - "4 Channel"
  - "128 x 128 x 128 Voxels"
  - "Uncompressed, 2 Bytes / Texel"
  - "4.194 Megabytes"
- **Content:** four labeled slice thumbnails = the four channels of the 3D noise texture:
  1. "**Low Freq "Curly-Alligator"**" — large feathery swirls.
  2. "**High Freq "Curly-Alligator"**" — same character, finer scale, higher contrast.
  3. "**Low Freq Alligator**" — large bright cells separated by dark crease network.
  4. "**High Freq Alligator**" — finer cells, denser crease network.
- **Reference (exact):** "Alligator Noise Code (via SideFX)" — "https://www.sidefx.com/docs/hdk/alligator_2alligator_8_c-example.html".
- So: one 128³ RGBA (4-channel, 2 bytes/texel presumably 16-bit? — slide says 2 Bytes/Texel total, uncompressed, 4.194 MB which matches 128³×2 bytes) noise volume holds both detail types at two frequencies.
- **Formulas/constants:** as quoted.

## Page 95
- **Title:** none.
- **Content:** Rendered cube of the 3D noise volume visualized in rainbow false color (each channel tinted; a chaotic multicolored voxel cube). Below, code (exact):
  ```
  // Apply wind offset
  inSamplePosition -= float3(cCloudWindOffset.x, cCloudWindOffset.y, 0.0) * voxel_cloud_animation_speed;
  ```
- Meaning: before sampling noise, the sample position is shifted opposite the accumulated wind offset (horizontal only, z untouched) scaled by `voxel_cloud_animation_speed` — this animates the detail noise with the wind.
- **Parameter names:** `inSamplePosition`, `cCloudWindOffset` (.x/.y used, 0.0 for z), `voxel_cloud_animation_speed`.

## Page 96
- **Title:** none.
- **Content:** Same rainbow noise cube, now with a camera icon and a red sample dot on a ray arrow (illustrating distance-based mip selection along the raymarch). Code (exact):
  ```
  // Sample noise
  float mipmap_level = log2(1.0 + abs(inRaymarchInfo.mDistance * cVoxelFineDetailMipMapDistanceScale));
  float4 noise = Cloud3DNoiseTextureC.SampleLOD(Cloud3DNoiseSamplerC, inSamplePosition * 0.01, mipmap_level);
  ```
- Meaning: mip level grows logarithmically with raymarch distance (scaled by `cVoxelFineDetailMipMapDistanceScale`); the 4-channel noise is sampled with an explicit LOD at `inSamplePosition * 0.01` (noise UVW scale constant **0.01**, i.e., one noise repeat per 100 world units).
- **Parameter names/constants:** `inRaymarchInfo.mDistance`, `cVoxelFineDetailMipMapDistanceScale`, `Cloud3DNoiseTextureC`, `Cloud3DNoiseSamplerC`, position scale `0.01`, mip formula `log2(1.0 + abs(distance * scale))`.

- **Title:** "**Dimensional Profile**" above a horizontal black→white gradient bar.
- **Content:** The gradient bar has two tick labels: near the dark end "**Low Frequency Wisps**", near the bright end "**High Frequency Wisps**". Code (exact):
  ```
  // Define wispy noise
  ```
