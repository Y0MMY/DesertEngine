## Page 141
**Header:** Nubis³ / Voxel Clouds / Lighting
**Title on slide:** "Nubis Ambient Scattering Approximation"
**Image:** Black slide with a flat light-grey cartoon cumulus silhouette. A darker grey rim outlines the upper portion of the cloud, and thin blue arrows point inward from all around the cloud toward its surface — illustrating ambient (sky) light arriving from every direction and penetrating a shallow shell of the cloud.
**Code (exact):**
```
float ambient_scattering = pow(1.0 - dimensional_profile, 0.5);
```
**Notes:** This is the base Nubis ambient approximation: ambient scattering is driven purely by the *dimensional profile* (the coarse cloud-shape field). Low profile values (thin edges / cloud exterior) → ambient near 1; deep interior (profile near 1) → ambient falls off as a square root. No directionality, no occlusion yet — that's what the following slides add.

## Page 144
**Header:** Nubis³ / Voxel Clouds / Lighting
**Image:** Diagram on black: a wireframe flat box labeled **256 Voxels × 256 Voxels** (horizontal extents) × **32 Voxels** (height). Inside are three small grey cartoon clouds; above/through each cloud a vertical arrow points upward with red dots along it — sample points where density is summed vertically (downward accumulation toward the sample: the red dots sit above/inside the clouds along the up-axis). This is a low-resolution 256×256×32 buffer of vertically summed ambient density.
**Code (exact, new term boxed on slide):**
```
float ambient_scattering = pow(1.0 - dimensional_profile, 0.5) * exp(-summed_ambient_density);
```
The `* exp(-summed_ambient_density);` term is highlighted with a white box (the new addition).
**Notes:** Ambient occlusion for clouds = Beer-Lambert extinction of sky light using density summed along the vertical (sky) direction, stored in a 256×256×32 voxel buffer. Multiplies the base profile-driven ambient term.

## Page 147
**Header:** Nubis³ / Voxel Clouds / Lighting
**Title/diagram:** A point light ("light pos", drawn as a small sun icon at the center of a blue radial glow) inside a large circle of influence labeled **radius**; a purple dot labeled "sample position" at distance **d1** from the light.
**Code (exact):**
```
potential_energy = pow( 1.0 - (d1 / radius), 12.0);
pseudo_attenuation = (1.0 - saturate(density * 5.0));
glow_energy = potential_energy * pseudo_attenuation;
```
**Notes:** Point-light "glow" model for lights inside clouds (e.g. lightning / bioluminescent effects): a sharply falling radial potential (power 12 falloff over the light radius), attenuated by a cheap pseudo-attenuation that kills the glow where local `density` is high (saturates at density ≥ 0.2, since density*5 clamps to 1).

## Page 159
**Header:** Nubis³ / Voxel Clouds / Ray-Marching
**Image:** Reproduction of the BCn compression-format table, "Source: https://www.reedbeta.com/blog/understanding-bcn-texture-compression-formats". Table columns: Type Of Data / Data Rate / Palette Size / Line Segments / Use For. Rows (as printed):
- BC1 — RGB + optional 1-bit alpha — 0.5 byte/px — 4 — 1 — Color maps, Cutout color maps (1-bit alpha), Normal maps if memory is tight
- BC2 — RGB + 4-bit alpha — 1 byte/px — 4 — 1 — n/a
- BC3 — RGBA — 1 byte/px — 4 color + 8 alpha — 1 color + 1 alpha — Color maps with full alpha, Packing color and mono maps together
- **BC4 — Grayscale — 0.5 byte/px — 8 — 1 — Height maps, Gloss maps, Font atlases, Any grayscale image** (highlighted with a white box)
- BC5 — 2 × grayscale — 1 byte/px — 8 per channel — 1 per channel — Tangent-space normal maps
- BC6 — RGB, floating-point — 1 byte/px — 8-16 — 1-2 — HDR images
- BC7 — RGB or RGBA — 1 byte/px — 4-16 — 1-3 — High-quality color maps, Color maps with full alpha
Right side text block: "**Precision Loss Symptoms**" — "Too low = extra steps" / "Too High = rendering artifacts".
**Notes:** Choosing a compressed format for the SDF: BC4 (grayscale, 0.5 byte/px) is the natural candidate. Precision trade-off stated for the SDF specifically: too little precision → conservative distances → extra march steps; too much (over-shooting distances) → rendering artifacts (surface leaks).

## Page 160
**Header:** Nubis³ / Voxel Clouds / Ray-Marching
**Image:** Left: "SDF — Uncompressed, 2 Bytes / Texel" (soft greyscale distance field, top view). Right: "SDF — BC1, 0.5 Bytes / Texel" — the same field visualized in false color (purple/blue/cyan contour bands) showing the quantized/banded distance values after BC1 compression.
**Code (exact):**
```
// Decompress BC1
dot(sampled_color.rgb, float3(1.0, 0.03529415, 0.00069204))
```
**Notes:** They compress the SDF with BC1 (0.5 bytes/texel, down from 2-byte uncompressed) and reconstruct a higher-precision scalar by encoding the distance across the R, G, B channels and decoding with a weighted dot product — weights 1.0, 0.03529415 (≈ 9/255), 0.00069204 (≈ 0.0451/65.16… effectively successive fractional digit scales). The false-color banding shows the residual quantization, acceptable for conservative step distances.
