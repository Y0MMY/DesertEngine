# Разбивка работ — программа «Небо и облака»

Автор: тимлид-архитектор. Источники: `REQUIREMENTS_SKY.md` (37 треб.), `REQUIREMENTS_CLOUDS.md` (53 треб.),
правила исполнения: `DEV_CONTRACT.md`.

Задачи нарезаны по одному принципу: **никакие две одновременно идущие задачи не правят один файл.**
Это не пожелание, а условие того, что мы вообще можем вести несколько разработчиков сразу.

---

## Волны

```
Волна 0 ──┬─ T1 хребет ECS ─────────────► (блокирует всё, что трогает Components.hpp)
          ├─ T3 3D-образы и форматы ────► параллельно, файлы не пересекаются
          ├─ T4 рефлексия сэмплеров ────► параллельно
          └─ T5 порядок в рендер-графе ─► параллельно

Волна 1 ──┬─ T2 миграция сцен ──────────► после T1
          ├─ T6 небо: проход и солнце ──► после T1

          └─ T11 пресеты и редактор ────► после T1, T2
```

## Волна 0

### T1 — Хребет ECS (владелец: Core)
Оба компонента со всеми полями и аннотациями, два поля на `DirectionalLightData`, ужатие
`SkyboxComponent`, регистрация во ВСЕХ семи местах чек-листа, перегенерация `Reflection.gen.cpp`.
Ничего не рендерит — это форма данных, на которую опираются все остальные.
**Файлы:** `ECS/Components.hpp`, новые заголовки компонентов, `Core/Serialize/ComponentRegistry.cpp`,
`ComponentEditorRegistrations.cpp`, `ComponentWidgetRegistry.cpp`, `EditorLayer.cpp`, `RuntimeLayer.cpp`,
`Engine/Generated/Reflection.gen.cpp`.
**Приёмка:** SKY-04…06, SKY-17, CLD-40…42; сборка обеих целей; поля видны в Details без единой строки
виджет-кода; тест перечисления полей рефлексии.

### T3 — 3D-образы, форматы, compute (владелец: Graphics-Core)
`Image3D` + спецификация + вулкановская реализация; `RGBA16F`; тотальный `GetBytesPerPixel` (CLD-18a:
удалить `return 0U`, чтобы неучтённый формат стал ошибкой компиляции); `ComputePipeline` для 3D;
сэмплеры шумов с явными LINEAR/REPEAT; **хелпер перехода слоя глубины** (CLD-13).
**Файлы:** `Graphic/Image.*`, `Core/Formats/ImageFormat.hpp`, вулкановские образы/пайплайны.
**Приёмка:** CLD-10, CLD-12, CLD-13, CLD-18, CLD-18a, CLD-96c, CLD-96e.

### T4 — Классификация сэмплеров в рефлексии (владелец: Shaders-Tooling)
Классифицировать по `type.image.dim`, а не по имени; `sampler3D`/`image3D` в DSL и парсере; проверка,
работающая без устройства (при необходимости — режим `--reflect` в `DShaderTool`).
**Файлы:** `VulkanShader.cpp`, `Tools/DShaderTool`, `DShaderParser`.
**Приёмка:** CLD-11, CLD-15. **Это самый дешёвый по коду и самый дорогой по последствиям пункт всей
программы:** сегодня `sampler3D` молча регистрируется как 2D — не падает, просто рисует мусор.

### T5 — Детерминированный порядок внутри фазы (владелец: Graphics-Core)
Стабильный тай-брейк в `RenderGraphBuilder`, тест сортировки, документация правила.
**Файлы:** `Graphic/Render/RenderGraphBuilder.*`.
**Приёмка:** CLD-19, CLD-96a. Задача маленькая и чинит примитив для всех, а не только для облаков.

## Волна 1

### T2 — Версия сцены и миграция (владелец: Core, после T1)
`SceneVersion`; **чистая функция над разобранным деревом до создания сущностей** — не по живой ECS-сцене,
прецедент `MigrateMetresToUnits` здесь неприменим; конвертация сцен репозитория; удаление автосейвов и
`.gitignore`; исправление солнца под горизонтом в четырёх сценах и в коде.
**Приёмка:** SKY-23…SKY-30, десять тест-кейсов миграции, включая намеренно битые поля.

### T6 — Небо: проход, солнце, IBL (владелец: Graphics-Sky, после T1)
Процедурное небо уезжает из `Skybox` (старый путь удаляется целиком); блок параметров неба как
std430 SSBO; `AtmosphereEnv` с непрозрачной ручкой буфера; правило выбора атмосферного солнца
(`SystemRules`, шесть случаев); драйвер времени суток; автоперепекание IBL.
**Приёмка:** SKY-01…03, SKY-09, SKY-16, SKY-18…22, SKY-35…37.

### T7 — Генерация шумовых объёмов (владелец: Shaders, после T3+T4)
S0: форма 128³, детализация 32³, curl. Детерминированные семена, CPU-эталон функций шума в тестах.
**Приёмка:** CLD-25…27.

## Волна 2

### T8 — Weather map и рейммарч (владелец: Shaders, после T7+T6)
S1 и S2. Оболочка в километровом пространстве, камера-относительная математика, запрет отдельного
радиуса планеты для облаков; пропуск пустоты без SDF; конусная выборка к солнцу; Beer + powder.
**Приёмка:** CLD-24, CLD-24a, CLD-28…31.

### T10 — Глубина и композит (владелец: Graphics-Core, после T3+T5)
S4 в фазе `Transparency`, до частиц; окклюзия решается внутри марша, глубинный тест выключен явно.
**Приёмка:** CLD-20…22, CLD-21a, CLD-29.

## Волна 3

### T9 — Темпоральная стадия (владелец: Graphics, после T8+T10)
S3. Репроекция только по камере; `Off` — полноценный протестированный путь, бит-в-бит равный выходу
рейммарча; таблица артефактов сверяется с реальностью и правится по факту.
**Приёмка:** CLD-32, CLD-32a, CLD-32b, CLD-34.

### T11 — Пресеты, качество, редактор (владелец: Editor, после T1+T2)
Таблицы пресетов (`constexpr`, один файл, одна строка на пресет), шкала качества, `ActivePreset` и
переход в `Custom` по отпечатку, проверка каждого поля от UI до GPU.
**Приёмка:** SKY-12, SKY-37, CLD-50…60, отсутствие мёртвых настроек.

## Что я проверяю на приёмке каждой задачи

1. Сборка обеих целей, `premake5 gmake2` при добавлении файлов.
2. `git clang-format` под llvm@18 по изменённым строкам.
3. Ни одного `TODO`, заглушки, мёртвого параметра.
4. Три случайных параметра трассируются от UI до шейдера.
5. Тесты на чистую логику падают, если сломать логику.
6. Отчёт разработчика с явно названными отклонениями.

Отклонение, названное самим разработчиком, обсуждается. Отклонение, найденное мной, — возврат.
