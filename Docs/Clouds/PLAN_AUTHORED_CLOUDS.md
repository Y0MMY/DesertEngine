Статус: **проект тимлида, к утверждению.** Написан 2026-08-20, пока файлы облаков заняты тремя
параллельными задачами.
Опирается на `ANALYSIS_APPROACH.md` §3 (вариант C), §4 (шов и два производителя), §6 (каталог форм) и

## 0. Почему эта фаза обязательна

Решение **D-4**: программа не закрывается до Э4. Это записано в момент, когда процедурный источник
только начинался, и записано именно затем, чтобы работающее процедурное небо не стало определением
наших облаков.

Сегодня у этого есть измеренное подтверждение. Три фазы подряд упирались в один и тот же предел:
**доли Alligator не сливаются по построению** — `best − second` кладёт ноль между каждой парой ячеек,
поэтому небо читается колодой отдельных подушек, а не одной кучевой массой. T2 измерил, T0 проверил,
что профиль на это не влияет по горизонтали, T3 проверил, что несколько полей размещения не
помогают. Три независимых замера, один вывод.

## 1. Что Э4 чинит, а что НЕТ — здесь надо быть точным

Я сам говорил про Э4 «она чинит подушки», и это неточно. Точно так:

- **Э4 не исправляет процедурное поле.** Дальний план остаётся процедурным и остаётся подушками.
- **Э4 даёт художнику ближний план**, где форма произвольна: сросшаяся кучевая масса, башня с
  наковальней, туннель, арка — всё, чего сумма несливающихся долей дать не может.

Это ровно сценарий §4.4 анализа: «художник поработал → P как фон + A ближнего плана с вырезом под
ним». Ценность не в том, что дефект исчезнет везде, а в том, что там, где смотрит игрок, форму
задаёт человек.

## 2. Бюджет памяти — арифметика, а не надежда

Решение D-9: **64 МБ на подсистему**. Занято сегодня (при кадре 1280×766):

| | размер |
|---|---|
| том шума `.dcnv` 128³ RGBA8 | 8.4 МБ |
| таблица профилей 256×64 RGBA32F | 0.26 МБ |
| две истории реконструкции + два guide, полуразрешение RGBA16F | ≈7.8 МБ |
| две цели трассировки, четвертное разрешение RGBA16F | ≈1.0 МБ |
| **итого** | **≈17.5 МБ** |

**Свободно около 46 МБ.**

Nubis держит modelling-том 512×512×64 при 8 м на воксель, и укладывается в 16.8 МБ **только благодаря
BC6**. У нас сжатия нет вовсе, и на Apple Silicon BC для 3D-текстур не экспонируется — тот же том
стоил бы 67 МБ и один съел бы весь бюджет.

Поэтому предлагаемый размер тома — **128×128×64 RGBA8 = 4.2 МБ**, и это влезает восемь раз.

**Почему это не деградация, а перенос работы.** Геройское облако — это ~2 км в поперечнике. При
128×128×64 на 2×2×1 км воксель равен 15.6 м. У Nubis 8 м, то есть вдвое мельче, — но доклад же и
говорит, что **8 м данных дают 0.5 м видимой детали**, потому что деталь несёт up-rez шумом, а не
воксель. Том несёт **силуэт**, шум несёт кромку. Мы уже построили обе половины: том — контейнером из
T2, шум — там же.

Если 15.6 м окажется мало, ответ известен заранее и записан в анализе §6: вкладываться в композицию
шума при up-rez, а не поднимать разрешение тома.

## 3. Откуда берётся форма

Houdini запрещён лицензионно, флюид-солвера не будет — это зафиксировано в анализе §6. Остаётся то,
что там же и предложено: **сумма сглаженных объёмных сгустков, объединённых экспоненциальным
smooth-min**.

Три свойства делают этот выбор не вкусовым:

1. Объединение **коммутативно и ассоциативно** — порядок примитивов не двигает результат, значит
   художник может лепить в любом порядке, а бейкер не обязан хранить порядок.
2. Его **softmax-веса естественно дают** каналы Detail Type и Density Scale — то есть два из четырёх
   каналов тома получаются побочным продуктом объединения, а не сочиняются отдельно.
3. Результат **есть нормированное поле расстояний** — ровно та величина, из которой Guerrilla
   получает Dimensional Profile (сл. 85), только полученная аналитически, а не distance transform'ом.

Каналы тома, как в статье плюс наш четвёртый:

| канал | что несёт |
|---|---|
| R | Dimensional Profile — насколько глубоко внутри тела |
| G | Detail Type — wispy ↔ billowy |
| B | Density Scale — повоксельный множитель |
| A | консервативная оболочка для пропуска пустоты |

## 4. Шов — уже готов и ждёт

`Common/CloudField.glslh` сегодня заканчивается так:

```glsl
// The seam itself. One producer that already unions up to four species; tomorrow the max of that and the
// authored one — the same `max`, one level up.
CloudFieldSample SampleCloudField( ... ) { return CloudSampleProceduralField( ... ); }
```

Это писалось в Э0 и пережило четыре фазы нетронутым. Слот A входит одной строкой.

Две детали обязательны и обе названы в анализе §4.3:

- **Вырез.** У экземпляра есть флаг «подавлять процедурное поле внутри моих границ». Без него сквозь
  вылепленное облако прорастает процедурная клякса.
- **Стоимость.** Авторский источник считается **только если позиция попала в AABB экземпляра**;
  экземпляров единицы. Ранний выход `if (Profile > 0)` делается один раз, после объединения.

⚠️ Атлас томов **привязывается всегда**, хотя бы фолбэком: `sampler3D` без изображения — невалидный
дескриптор, и compute-диспатч молча не исполняется. Это грабли, на которых подсистема уже стояла.

## 6. Чего эта фаза НЕ делает

- Не пишет флюид-солвер: «цветная капуста» с с. 69 доклада даётся симуляцией, и это зафиксировано как
  сознательное ограничение.
- Не поднимает разрешение тома ради детали — деталь несёт up-rez (§2).
- Не исправляет процедурный дальний план (§1).
- Не берёт сжатие: BCn в дереве нет, на Apple Silicon для 3D не экспонируется.
